# On Air Clock V2: Design

Stand: 2026-11-11 · Branch: `v2`

Markierungen: **(entschieden)** hat der Maintainer festgelegt. **(Vorschlag)** ist eine Entscheidung aus dem Brainstorming, die der Maintainer beim Review bestätigen oder ändern kann. **(Builder)** bleibt bewusst offen.

---

## 1. Worum es geht

On Air Clock ist ein Stream-Deck-Plugin, das eine Studiouhr im Broadcast-Stil auf eine Taste bringt: ein Ring aus 60 Sekundenpunkten mit der Uhrzeit in der Mitte. V1 funktioniert, ist aber technisch und optisch in die Jahre gekommen. Es basiert auf dem alten HTML-Template von Elgato und zeichnet mit Canvas. Viel Template-Code ist ungenutzt, Einstellungen werden doppelt geparst, jede Taste hat einen eigenen 250-ms-Timer mit Logausgabe, und es gibt keine Tests. Branding und Marketing wirken laut Maintainer „gefummelt und oldschool“.

V2 baut das Plugin auf einer sauberen, modernen Grundlage neu. Es behebt die offenen Issues, bringt neue Watchfaces und einen Countdown, bekommt ein neues Branding und soll im **Elgato Marketplace** erscheinen.

**Zielgruppe:** vor allem Streamer und Desktop-Nutzer, dazu einige Leute in professionelleren Studios. Studio-Profis nutzen meist Bitfocus Companion statt des Stream-Deck-Plugins.

## 2. Ziele, Nicht-Ziele, Anti-Ziele

**Ziele**
- Release im Elgato Marketplace (entschieden).
- Kompletter Neubau mit deutlich besserer Codequalität (entschieden).
- Nahtloses Update für bestehende Installationen: gleiche Plugin-ID, vorhandene Tasten behalten ihre Einstellungen (entschieden).
- Alle Stream-Deck-Modelle mit Display, inklusive Touch-Display des Stream Deck+ (entschieden).
- Zeitzone pro Taste, das löst Issue #2 und #10 (entschieden).
- Countdown, das löst Issue #7 (entschieden).
- Neue Watchfaces und Mikroanimationen (entschieden).
- Neues Branding in Richtung „Farbraum“ (entschieden).

**Nicht-Ziele**
- Bitfocus Companion (entschieden).
- Eine Uhr über mehrere Tasten (Issue #5). Wurde als Mockup getestet und verworfen, weil es nicht gut aussieht (entschieden).
- Die Faces „Striche“ und „Analog“ aus den Mockups (entschieden).
- Pause-Funktion für den Countdown, Stoppuhr oder Hochzählen, Töne (Vorschlag).
- Navigation zu Ordnern oder Profilen per Tastendruck aus #7. Das Stream-Deck-SDK erlaubt Plugins keinen Sprung in vom Nutzer angelegte Ordner (Vorschlag).
- Ein Countdown, der einen Neustart der Stream-Deck-Software überlebt (Vorschlag).

**Anti-Ziele.** Folgendes wäre ein Fehlschlag, auch wenn alles technisch funktioniert:
- Nach dem Update sind bestehende Tasten leer, kaputt oder auf Standardwerte zurückgesetzt.
- Die Uhr belastet CPU oder Stream-Deck-Software spürbar, zum Beispiel wenn viele Uhren gleichzeitig sichtbar sind.
- Die Uhr zeigt eine falsche Zeit, und der Nutzer hat keine Möglichkeit, das zu korrigieren.
- Der Marketing-Auftritt wirkt wieder generisch oder zusammengebastelt.

## 3. Feste Rahmenbedingungen

- **Plugin-ID bleibt** `fail.marc.onairclock`, die Uhr-Aktion bleibt `fail.marc.onairclock.action`, der Plugin-Ordner bleibt `fail.marc.onairclock.sdPlugin` (entschieden).
- **V1-Einstellungen müssen gelesen und migriert werden.** V1 speichert pro Taste folgende Werte, alle als Strings aus Select- und Color-Inputs. Fehlt ein Wert, galt in V1 der Default.

  | Schlüssel | Werte in V1 | Bedeutung |
  |---|---|---|
  | `watchface` | `"0"`–`"4"` | 0 Default, 1 ohne Datum, 2 ohne Sekunden, 3 ohne Datum und Sekunden, 4 Modern Minimal |
  | `dateType` | `dd-mm`, `mm-dd`, `dd-mm-yy`, `mm-dd-yy`, `yy-mm-dd` | Datumsformat, Default `dd-mm` |
  | `hourFormat` | `"24"`, `"12"` | Default `"24"` |
  | `ampmindicator` | `"true"`/`"false"` oder Boolean | PM-Markierung im 12h-Modus |
  | `dotcolor` | Hex | aktive Farbe, Default `#ab0000` |
  | `inactivecolor` | Hex | inaktive Punkte, Default `#888888` |
  | `backgroundcolor` | Hex | Hintergrund, Default `#000000` |

  Ungültige Werte behandelt V1 als Default. V2 muss sich genauso verhalten. Alte Template-Reste wie `mynameinput` werden ignoriert.
- **Plattformen:** macOS und Windows, alle Stream-Deck-Modelle mit Display (entschieden). Die Mindestversion der Stream-Deck-Software ergibt sich aus dem gewählten SDK (Builder).
- **Marketplace:** Manifest, Icons und Vorschaubilder müssen die aktuellen Richtlinien des Elgato Marketplace erfüllen. Der Builder prüft sie zu Beginn. Die Einreichung selbst macht der Maintainer.
- **Sprachen:** Englisch und Deutsch, wie in V1 (Vorschlag).
- **Version:** 2.0.0.

## 4. Technische Grundlage

- **Aktuelles offizielles Node.js-SDK von Elgato** (`@elgato/streamdeck`) mit **TypeScript** und der **Elgato CLI** (`@elgato/cli`) für Erstellen, Verlinken, Validieren und Packen (entschieden: „aktuelles SDK, SVG“).
- **Darstellung als SVG**, die per `setImage` an die Taste geht. Auf dem Stream Deck+ geht sie per Feedback an das Touch-Display. Kein Canvas (entschieden).
- **Ziffern als eigene Linienpfade**, keine Schriftart. So sieht die Uhr auf Mac und Windows identisch aus und skaliert sauber. Einen funktionierenden Prototyp-Satz für `0–9 : - +` gibt es im Mockup (siehe Abschnitt 10) (Vorschlag).
- **Ein gemeinsamer Takt für alle Instanzen** statt eines Timers pro Taste. Neu gezeichnet wird ausgerichtet an der Sekundengrenze. Während einer Animation kurzzeitig häufiger, sonst nur, wenn sich das Bild ändert (Vorschlag).
- **Saubere Trennung** in reine, testbare Module (Zeitmodell, Countdown-Zustand, Settings-Migration, Face-Renderer) und eine dünne SDK-Schicht (Vorschlag).
- **Property Inspector** im Stil der Stream-Deck-Software. Elgatos `sdpi-components` liegen nahe (Builder).

## 5. Uhr-Aktion (`fail.marc.onairclock.action`)

### 5.1 Watchfaces

| Face | Herkunft | Beschreibung |
|---|---|---|
| **Klassik** | V1 Default | 60 Punkte, 12 Stundenmarken, Uhrzeit, optional Datum und Sekunden. Deckt V1-Faces 0–3 über die Optionen „Datum anzeigen“ und „Sekunden anzeigen“ ab. |
| **Modern Minimal** | V1 Face 4 | Bleibt für bestehende Nutzer erhalten (Vorschlag). Bekommt die neuen Ziffern. |
| **Linie** | neu | Durchgehender Bogen statt Punkten, leuchtender Kopf am Ende, darunter dünner Hintergrundring. Uhrzeit groß, Sekunden klein darunter. |
| **Komet** | neu | Haarlinie als Ring, darauf läuft ein Lichtpunkt mit ausklingendem Schweif. Stunden und Minuten groß übereinander. |
| **Groß** | neu | Stunden und Minuten maximal groß übereinander, Sekundenfortschritt als dünne Linie am unteren Rand. Für Ablesen aus der Entfernung. |

Bestehende Tasten bekommen beim Update die neuen Ziffern und die überarbeitete Optik. „Nahtlos“ heißt: Die Einstellungen bleiben erhalten und alles funktioniert weiter. Es heißt nicht, dass jedes Pixel gleich bleibt (entschieden).

**Standardwerte:** V1 speichert eine Einstellung erst, wenn der Nutzer sie ändert. Eine nie eingestellte V1-Uhr hat deshalb leere Settings und ist von einer neuen Taste nicht zu unterscheiden. V2 wendet seine neuen Standardwerte (Farben, Animationen an usw.) auf **alle** Tasten ohne gespeicherten Wert an, also auch auf nie eingestellte V1-Uhren (entschieden). Gespeicherte V1-Werte werden immer übernommen.

### 5.2 Einstellungen pro Taste

- Watchface, Datum anzeigen und Sekunden anzeigen. Welche Faces welche Optionen unterstützen, entscheidet der Builder. Klassik muss beide unterstützen.
- Datumsformat (die fünf V1-Formate), 12/24h, PM-Markierung.
- Farben: aktiv, inaktiv, Hintergrund (V1-Parität).
- **Zeitzone:** „Systemzeit“ (Default), eine IANA-Zeitzone aus einer Liste oder ein **fester UTC-Versatz** in 15-Minuten-Schritten (Vorschlag).
- **Beschriftung** (optional, kurz, zum Beispiel „NYC“) für Weltzeituhren. Wie und wo sie erscheint, entscheidet der Builder. Sie muss lesbar sein und darf die Uhrzeit nicht überdecken. Die native Titel-Funktion der Stream-Deck-Software ist eine mögliche Lösung (Builder).
- **Animationen** an/aus (Default an, entschieden) und **Doppelpunkt blinkt** an/aus (Default an) (Vorschlag für die Aufteilung in zwei Schalter).
- **Countdown anzeigen:** Checkbox, ob diese Uhr einen Countdown übernimmt oder immer die Uhrzeit zeigt (entschieden). Default an (Vorschlag). Damit kann man zum Beispiel Weltzeituhren ausnehmen.

### 5.3 Zeitzonen und Issue #10

Nutzer in British Columbia sehen nach der dortigen Umstellung auf dauerhaft UTC-7 eine Stunde Abweichung. Laut Issue-Kommentar haben Elgatos eigene Uhr-Plugins dasselbe Problem. Vermutlich bringt die Laufzeitumgebung der Stream-Deck-Software veraltete Zeitzonen-Daten mit.

**Anforderung:** Betroffene müssen die richtige Zeit einstellen können, ohne auf ein Update von Elgato zu warten. Mindestlösung ist der feste UTC-Versatz. Der Builder prüft, ob „Systemzeit“ in der Node-Laufzeit von Stream Deck dasselbe Problem hat. Er entscheidet auch, ob eigene, aktuelle Zeitzonen-Daten mitgeliefert werden.

### 5.4 Mikroanimationen

Alle aus dem Mockup ausgewählt (entschieden):
- **Ziffern rollen:** Geänderte Ziffern gleiten nach oben weg, die neuen kommen von unten. Etwa 0,4 s, nur Verschieben und Ausblenden, kein Clipping.
- **Ring-Reset:** Zur vollen Minute läuft der volle Ring sich selbst hinterher, statt zu verschwinden. Etwa 0,75 s.
- **Doppelpunkt blinkt** im Sekundentakt.
- **Nachglühen:** Die aktuelle Sekunde oder der Ringkopf leuchtet hell und klingt weich aus.

Alle Animationen müssen bei niedriger Bildrate sauber degradieren. Bei 1 Bild/s springen sie einfach, ohne Artefakte. Welche Bildrate pro Taste vertretbar ist, wird auf echter Hardware gemessen (siehe Abschnitt 8).

### 5.5 Stream Deck+

Das Touch-Display zeigt die Uhr wie in V1 (V1-Parität). Ob Drehregler oder Druck eine Funktion bekommen, entscheidet der Builder.

## 6. Countdown-Aktion (neu)

Eine eigene Taste mit fest eingestellter Dauer. Ein Druck startet den Countdown auf der Uhr. Die Konfiguration erfolgt in der Stream-Deck-Software (entschieden).

- **Dauer:** Minuten und Sekunden, bis 99:59 (Vorschlag).
- **Ziel:** Pro Stream Deck gibt es **genau einen Countdown** (Vorschlag). Ihn zeigt jede Uhr auf diesem Gerät, bei der „Countdown anzeigen“ angehakt ist (entschieden, siehe 5.2). Das gilt auch für Uhren, die erst nach dem Start sichtbar werden, etwa nach einem Seiten- oder Ordnerwechsel (Vorschlag). Der Countdown wird also pro Gerät gehalten, nicht pro Uhr. Die Countdown-Taste hat keine eigene Zielauswahl.
- **Darstellung auf der Uhr:** Der Ring zeigt die Restzeit (voll beim Start, leer bei 0), die Ziffern zeigen `MM:SS`. Wie das in jedem Face aussieht, zeigt das Mockup.
- **Bei 0, einstellbar:**
  - **Überziehen zählen** (Default, entschieden): läuft als `+MM:SS` weiter hoch, der Ring blinkt. Das ist bei Broadcast- und Bühnen-Timern üblich.
  - **Bei 00:00 stehen bleiben:** blinkt, bis man es beendet.
  - **Zurück zur Uhrzeit:** kurzes Aufblitzen, danach wieder die Uhrzeit.
- **Warnung in den letzten 10 Sekunden** (Pulsieren): Option, standardmäßig aus (Vorschlag).
- **Bedienung** (Vorschlag):
  - Ein erneuter Druck auf die Countdown-Taste während eines laufenden, stehenden oder überzogenen Countdowns **bricht ab**. Die Uhr zeigt wieder die Uhrzeit.
  - Ein Druck auf eine Uhr mit laufendem Countdown bricht ebenfalls ab.
  - Wird ein zweiter Countdown gestartet, ersetzt er den ersten auf den betroffenen Uhren.
- **Zeitbasis:** Der Countdown rechnet mit einem Start-Zeitpunkt, nicht mit Ticks. Nach einem Seitenwechsel und zurück stimmt die Restzeit (Vorschlag).
- **Keine Uhr sichtbar:** Die Countdown-Taste zeigt den Countdown selbst an (Vorschlag).
- **Aussehen der Countdown-Taste:** zeigt im Ruhezustand die eingestellte Dauer, während des Laufs einen erkennbaren Zustand. Die Details entscheidet der Builder.

## 7. Branding und Marketing: Richtung „Farbraum“

Der Maintainer hat Richtung C aus dem Mockup gewählt. Die Grafiken erstellt der Builder (entschieden).

- **Idee:** Die frei wählbaren Farben sind die Marke. Ein kräftiges Ultramarin dient als Bühne, darauf echte schwarze Stream-Deck-Tasten mit Uhren in verschiedenen Farben und Faces.
- **Farben:** Ultramarin `#2B3BFF`, Papier `#F2F3FF`, Tasten-Schwarz `#000000` sowie die Uhrfarben Rot `#FF3B2F`, Mint `#3DFFB5` und Amber `#FFA516`. Im Mockup kommen zusätzlich Weiß `#F4F4F4`, Blau `#5B8CFF` und Pink `#FF5FD2` vor.
- **Schriften (nur Marketing):** Unbounded für den Namen und Überschriften, Barlow für Text. Beide gibt es frei bei Google Fonts. Im Plugin selbst werden nur die eigenen Ziffernpfade verwendet.
- **Name:** „On Air Clock“ bleibt (Vorschlag).
- **Claim:** EN „Studio clocks in any color, on any key.“ / DE „Studiouhren in jeder Farbe, auf jeder Taste.“ (Vorschlag). Die Uhr über mehrere Tasten taucht nirgends auf.
- **Texte:** Plugin-Beschreibung (EN und DE) und README neu schreiben. Schlicht und konkret: was die Uhr kann (Faces, Farben, Zeitzonen, Countdown), kein Werbesprech.
- **Zu erstellende Assets:**
  - Plugin-Icon und Kategorie-Icon
  - Icons für die Uhr- und die Countdown-Aktion
  - Standard-Tastenbilder
  - Marketplace-Vorschaubilder für Faces, Farben, Zeitzonen und Countdown
  - README-Hero mit animierter Vorschau
  - GitHub-Social-Preview

  Formate und Größen nach den Marketplace-Richtlinien (Builder prüft). Die alten Assets (`previews/`, `pi.png`, `preview.gif`, `.afdesign`) werden ersetzt.

## 8. Risiken: früh auf Hardware prüfen

1. **SVG-Unterstützung der Stream-Deck-Software:** Welche SVG-Features rendert sie auf den Tasten, zum Beispiel radiale Verläufe für das Leuchten, Deckkraft, Transformationen? Das prüft der Builder mit einem frühen Spike. Fallbacks sind erlaubt: Leuchten über gestaffelte, halbtransparente Kreise statt über Verläufe.
2. **Bildrate und Last:** Was ist pro Taste vertretbar, wenn zum Beispiel 15 Uhren gleichzeitig sichtbar sind, auf einem XL und auf einem Stream Deck+? Daraus ergibt sich das Animationsbudget.
3. **Zeitzonen-Daten der Node-Laufzeit** (siehe 5.3).
4. **Settings-Migration:** mit echten V1-Profilen testen. Dazu V1 installieren, Tasten konfigurieren, V2 darüber installieren.

**Vorhandene Hardware:**
- Am Entwicklungs-Mac hängt ein Stream Deck MK.2 (5×3). Darauf laufen die Spikes und Messungen.
- Ein Stream Deck+ steht beim Maintainer im Büro. Dafür bekommt er eine kurze Test-Checkliste.
- Einen Windows-Rechner gibt es nicht. Windows wird über eine Beta-Checkliste abgedeckt. Die Reporter aus #10 sind mögliche Tester (Vorschlag).
- Die Stream-Deck-Software darf auf die Version aktualisiert werden, die das SDK braucht (entschieden).

Animationen bleiben standardmäßig an (entschieden). Zeigt die Messung zu hohe Last, werden die Animationen sparsamer: geringere Rate, kürzere Phasen. Abgeschaltet werden sie nicht.

**Entwicklung ohne Risiko für echte Profile** (Vorschlag): Auf dem Entwicklungs-Mac ist V1 mit echten Profilen installiert. Entwickelt wird deshalb unter einer eigenen Dev-Plugin-ID, zum Beispiel `fail.marc.onairclock.dev`, die neben V1 läuft. Die echte ID kommt nur für den Migrationstest zum Einsatz, und das erst nach einem Backup des Stream-Deck-Profilordners.

## 9. Repo und Qualität

- **Tests** (Vitest oder vergleichbar) für alle reinen Module:
  - Zeitmodell: Zeitzonen, UTC-Versatz, 12/24h, Datumsformate
  - Countdown-Zustandsmaschine mit allen drei Endmodi
  - V1→V2-Migration
  - Face-Renderer, als Snapshot oder Struktur-Test
- **Lint und Format**, TypeScript im strict-Modus.
- **CI auf GitHub Actions:** Lint, Tests, Build, `streamdeck validate`. Bei einem Tag wird gepackt und die `.streamDeckPlugin`-Datei als Release-Asset angehängt.
- **Aufräumen:**
  - Die Binärdatei `DistributionTool` wird durch die Elgato CLI ersetzt.
  - `release/*.streamDeckPlugin` fällt weg. Die Dateien hängen bereits an den GitHub Releases.
  - `deploy.sh` wird durch `streamdeck link` und `streamdeck restart` ersetzt.
  - Der alte Template-Code (`common.js`, `common_pi.js`, `timers.js`, `sdpi.css`) entfällt.
- **README** neu: Installation über Marketplace und GitHub Release, Entwicklung mit der CLI, Hinweis zu Zeitzonen und UTC-Versatz.
- **Issues:** #2, #7 und #10 werden mit V2 geschlossen, #5 wird mit Begründung geschlossen. Die Kommentare formuliert der Builder, posten und schließen tut der Maintainer.
- Der alte Remote-Branch `buttonfunction` (Experiment von 2023) ist gelöscht.
